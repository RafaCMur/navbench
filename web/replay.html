A*

Drafts a grid of 5 cm cells on the house and marks the cells the robot does not fit in. It then searches outward from the start, always expanding the most promising cell first. It returns the shortest route on that grid, and the same route every time.

The cost grows with the number of cells, so with the size of the house and the cell size. It is cheap in a small map and about the same on every run: the median here is 58 to 89 ms, mostly spent building the grid.

RRT*

Samples random points in the free space and grows two trees toward them, one from the start and one from the goal. When it finds a shorter connection between branches, it rewires the tree to use it. It stops when the two trees meet, so the route depends on where the random points fall.

The cost grows with the number of random points it needs, which depends on how hard the space is. It is cheap in open space and costly in narrow passages. It also varies a lot between runs, from 2 to 278 ms here.

What I found

On average, A* found the shorter path on every route, and the same path every time. RRT* varied from run to run. From the kitchen to the bedroom it used the short hallway in only of 30 runs and went around through the bathroom in the others. The hallway is narrow and has a bend, so random points rarely land inside it before the two trees connect elsewhere.

A* is not always shorter. From the bathroom to the bedroom the best RRT* run ( m) beat A* ( m). A* moves between neighbouring cells, while RRT* can connect two points at any angle.

RRT* was usually faster to plan here, but mostly because of the grid. A* spends most of its time building the grid rather than searching it. In a small house this is cheap. In a large map, or one that changes often, the grid has to be rebuilt each time and the cost grows.

Limits

This is a single small 2D house with a round robot that drives at constant speed. The robots have no sensors. When the hallway closes, they are told and plan again from their current position. PyRoboSim's RRT* stops as soon as its two trees meet, so it does not keep improving the route given more time, as RRT* can in principle. The times were measured on one laptop and vary between machines. The path lengths do not.

The world, the robot and both planners come from PyRoboSim by Sebastian Castro (MIT license). The paths were planned by PyRoboSim in Python, and this page only replays them.
