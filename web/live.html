How the live mode works

A web page cannot run Python, and PyRoboSim is Python. So I wrote A* and RRT* again in JavaScript, which every browser can run. The code is in planners.js. It copies PyRoboSim's code step by step and uses the same settings.

The planners also need a map. The robot is not a point. It has a size, so its centre cannot go right up to a wall. PyRoboSim works out where the centre can safely be, and I saved that area from Python. A* keeps 15 cm away from walls and furniture. RRT* keeps 10 cm, which is the radius of the robot.

A* puts a grid of 5 cm squares over the house and searches it square by square. My grid has the same squares as PyRoboSim's, and A* finds the same route as PyRoboSim on all four benchmark routes.

RRT* picks random points, so it needs random numbers. A seed is a number that fixes those choices: the same seed gives the same points. I used the same random number generator as NumPy, the Python library PyRoboSim uses. In 71 of the 120 benchmark runs (four routes, 30 seeds each) the route is identical to the Python one. In the others it starts out the same and then splits off. The reason is tiny. JavaScript and Python sometimes disagree about a sine or cosine in the last digit. RRT* only links two points that are at most 50 cm apart, and a step of exactly 50 cm can come out a hair under the limit in Python and a hair over it in JavaScript. One point is kept in one language and dropped in the other, and from then on the two trees grow differently. Over 30 seeds the routes have about the same length.

The times on this page are measured in your browser. They cannot be compared with the times in Replay, which were measured in Python on my laptop.

The world, the robot and both planners come from PyRoboSim by Sebastian Castro (MIT license). The JavaScript planners follow its code.
