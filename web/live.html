How the live mode works

PyRoboSim is written in Python, which a web page cannot run. I therefore reimplemented A* and RRT* in JavaScript (planners.js), following the PyRoboSim source step by step and using the same parameters.

Both planners also need a map of where the robot can go. Because the robot has a physical size, its centre cannot approach a wall arbitrarily closely. PyRoboSim computes the region where the centre is allowed to be, and I exported that region from Python. A* keeps 15 cm clear of walls and furniture. RRT* keeps 10 cm, the radius of the robot.

A* overlays a grid of 5 cm cells on the house and searches it cell by cell. My grid is identical to PyRoboSim's, and A* returns the same route as PyRoboSim on all four benchmark routes.

RRT* samples random points, so its result depends on the random number generator. A seed fixes the sequence: the same seed gives the same samples. I implemented the generator that NumPy uses, which PyRoboSim relies on. In 71 of the 120 benchmark runs (four routes, 30 seeds each) the route matches the Python one exactly. In the remaining runs the two trees start out identical and later diverge. The cause is a floating-point difference: JavaScript and Python occasionally return a sine or cosine that differs in the last digit. RRT* only connects points that are at most 50 cm apart, so an edge of exactly 50 cm can fall just under the limit in Python and just over it in JavaScript. One implementation then accepts the point and the other rejects it, and the trees grow differently from there. Averaged over 30 seeds, the route lengths are about the same.

The times on this page are measured in your browser. They are not comparable with the times in Replay, which were measured in Python on my laptop.

The world, the robot and both planners come from PyRoboSim by Sebastian Castro (MIT license). The JavaScript planners follow its code.
